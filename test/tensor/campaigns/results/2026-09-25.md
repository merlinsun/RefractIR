# Triton tensor campaign results

## Scope and result

The campaign compared the existing tensor-v1 generator with tensor-v2 multi-input composition using ordinary and error-directed inputs on one Tesla V100-SXM2-32GB (SM70). Triton was pinned to `e2e356723ce35f46b5144373b145c55c4d712237` (3.8.0), with Python 3.10.12, PyTorch 2.10.0+cu128, CUDA 12.8, and driver 535.274.02.

No new Triton defect was found in the bounded runs. This result describes the tested generator strata, inputs, launch configurations, and compiler revision; it does not establish that Triton is free of defects.

The authored [PR #11186 calibration fixture](../../regressions/triton-11186/case.json) passed the calibration gate through the SIR-to-Triton path. The affected full build (`446f56ffd12431b1760ed504b7bcfdb6bb7b93c9`) produced 256 mismatches with maximum absolute error 256; the corrected build (`e2e356723ce35f46b5144373b145c55c4d712237`) passed the same fixture. TTGIR triage confirmed the OptimizeThreadLocality reduction-reordering defect.

The frozen rediscovery experiment generated 128 fresh tensor-v2 `loop-reduction` i32 cases with seeds 20260926 through 20261053. All passed on both builds, so zero cases exposed the calibrated defect. The campaign ended with `budget_exhausted_without_rediscovery`; the six-hour cap was not a promise that rediscovery would occur. No independent held-out fixture was verified, and no generator-generalization claim is made.

## Fixed-count sensitivity

The fixed-count protocol targeted 100 completed executions per arm. Tensor-v1 and tensor-v2 ordinary each completed 100 passing cases. Tensor-v2 directed completed 62 passing cases and had 38 graph-selection shortfalls. The directed arm accepted only cases satisfying both the shared admissibility predicate P and distinguishing objective D. Its shortfalls remain in the record, so the campaign status is `count_shortfall` and the equal-count comparison is invalid.

The ordinary arm distinguished 62 of its 100 accepted cases. All 62 directed cases satisfied D. There were no compiled wrong results or other failing cases. The fixed-count cache-isolation check passed for all 262 completed executions.

## Fixed-time throughput and coverage

Each arm received 3,600 seconds on GPU 0, with serial execution and an empty compiler cache for every case. Unequal completion counts are reported as throughput outcomes.

| Arm | Completed passing runs | Directed-selection shortfalls | Unique source structures | Unique TTIR/TTGIR structures | Runs per hour |
| --- | ---: | ---: | ---: | ---: | ---: |
| Tensor-v1 existing generator | 524 | 0 | 267 | 98 | 524 |
| Tensor-v2 composition, ordinary inputs | 516 | 0 | 355 | 355 | 516 |
| Tensor-v2 composition, directed inputs | 454 | 395 | 581 across attempted cases | 321 | 454 |

All completed cases passed their reference comparison. The directed arm made 849 graph attempts: 454 selected inputs passed P and D, and 395 attempts ended in `directed_shortfall`. The ordinary arm passed P for all 516 cases; D held for 273 and did not hold for 243. The ordinary and directed arms completed 273 same-seed graph pairs.

The normalized compiler coverage index contains 1,889 case records, 848 distinct source signatures across all arms, 1,494 distinct LLVM signatures, 1,494 distinct PTX signatures, 583 TTIR signatures, and 583 TTGIR signatures. Per-arm counts appear in the table. The fixed-time run used the `multi-input-composition` stratum, so it produced zero source-loop cases and zero compiled-loop cases; it makes no loop-coverage claim.

The fixed-time ledger reports compilation costs of 1,561.9 seconds for tensor-v1, 1,556.4 seconds for ordinary tensor-v2, and 1,370.4 seconds for directed tensor-v2. Reference validation consumed 3.5, 22.4, and 360.1 seconds respectively. The directed arm's additional reference work and 395 selection shortfalls reduced its completed-run throughput under the same wall-clock budget.

Cache isolation passed for all 1,494 completed fixed-time cases. Each case began with its own empty cache, a stricter policy than sharing a cache within an arm.

The comparison between tensor-v1 and tensor-v2 changes the generator, dtype, property family, and source structure together (f32 softmax versus i32 composition). It measures these campaign arms as declared, but cannot isolate composition as the cause of any difference. The ordinary-versus-directed comparison uses the same tensor-v2 graph seeds and input domain and is the controlled input-selection comparison.

## Runner correction and validation

The first fixed-time launch stopped before generating GPU cases because the runner read a different budget field from the frozen manifest. The runner normalizes `wall_clock_budget_s_per_arm` before starting an arm; the r2 manifest records this fixed-time-only amendment, and the completed fixed-time run used the unchanged budgets, seeds, selection policy, compiler, and environment pins.

The local Python evaluation and campaign-driver suites passed all 42 tests. Ruff lint and format checks, Python compilation, JSON parsing, and `git diff --check` passed. The same 42 tests passed through `make test-tensor-evaluation` on the remote environment. The local Make target could not be invoked because Makefile parsing requires Bitwuzla through `pkg-config`, which is absent locally. A full C++/solver suite was not run for this campaign.
